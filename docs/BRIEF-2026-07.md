## 1. What we are building

**One platform, three verbs: BUILD / DEPLOY / MONETIZE.** Platform-agnostic.
Framework-agnostic. Built on Solana.

Each leg has exactly one differentiator:

| Leg | Differentiator | One-liner |
|---|---|---|
| **BUILD** | Framework-agnostic import | Bring an agent from GitHub — Mastra, ElizaOS, LangChain, AutoGen, CrewAI, or custom — and it runs here |
| **DEPLOY** | Decentralized per-second GPU | Agents run on Nosana's decentralized GPU network, billed per second, not per month |
| **MONETIZE** | Receipts-backed marketplace | Four pricing modes (free / per-request / monthly / tokenized), every earning backed by an on-chain receipt |

**What the closed loop is — and what it is not.** An agent's token launch routes trading
fees into an on-chain treasury PDA, which pays the agent's own compute bill, attested
on-chain by a reputation oracle:

```
  token trading fees                on-chain treasury (PDA)
        │                                   │
        ▼                                   ▼
  fee router ──────────────────▶  agent-treasury program ────▶ pay_nosana
                                            │                     │
                                            │                     ▼
                                            │              Nosana GPU compute
                                            ▼                     │
                                  reputation-oracle  ◀────────────┘
                                  (usage attestations → eligibility)
```

This loop — "agents pay for themselves" — is **not the moat and not the headline**.
Virtuals already runs a compute buyback loop; the mechanism is copyable. It is the
monetize leg's **trust feature**: the proof that tokenized agents here are not memecoins.
It should be reachable from every buy surface and lead none of them.

**The honest defensibility statement:** no single leg is intrinsically a moat — each has
strong incumbents. Defensibility = the **bundle** plus credibility in the
Solana / framework-agnostic / decentralized-GPU niche, won by being early and by being
*verifiably honest* (see §3).

**Dogfood proof-agent:** WheelsHelper (`examples/reference-agents/wheels-helper/`), an
ElizaOS character that exercises every layer — build → deploy → tokenize → auto-pay —
with its own unit suite (`apps/api/src/tests/wheelsHelperReference.unit.test.ts`).

**Lead with BUILD.** It is the only leg whose expensive core is real end-to-end, and the
two-minute demo — register → import from GitHub → chat with real streaming inference —
works today with zero backend changes.

## 5. Honest risks & kill conditions

**Risks, in order of severity:**

1. **Fabrication risk (self-inflicted, live today).** The product's pitch is
   verifiability while its funnel fabricates (§3 Tier 4). One caught fake discredits
   every real receipt. Mitigation: Phase A deletes every fabricated surface before
   anything ships publicly.
2. **Distribution cold-start.** A receipts-backed marketplace with zero external
   creators shows $0 everywhere — honest but empty. Mitigation: WheelsHelper +
   founder-launched agents seed the loop; hackathon + grant channels (§4 calendar) are
   the distribution wedge.
3. **Sybil-farmable gate.** Reputation from self-usage can be farmed. Interim
   limitation is documented; the x402 rail (Phase B) weights externally-paid usage,
   which costs a sybil real money.
4. **Solo-builder surface mismatch.** ~40 dashboard routes for one builder; demo-ware
   breadth dilutes the real 20%. Mitigation: Phase B flag-gates the breadth behind an
   "Advanced" group, default off.
5. **Nosana concentration.** One GPU network, no fallback; if Nosana can't serve
   production inference, the deploy differentiator dies with it.

**Kill conditions (set by this brief, decided at the stated checkpoints):**

- **K1 — Loop truth (end of Phase A):** if the closed loop cannot complete one honest
  end-to-end run on devnet (tokenize → fees → treasury → pay Nosana → attestation),
  stop pitching the loop entirely until it can.
- **K2 — Buyer existence (4 weeks after Phase B ships):** if a working Install flow +
  honest marketplace produce zero external installs or paid requests, the marketplace
  thesis is wrong — refocus on BUILD+DEPLOY as a dev-tool and shelve monetize.
- **K3 — Deploy viability (Phase B):** if Nosana nodes cannot pass health checks and
  serve real inference at tolerable latency/cost, drop the decentralized-GPU
  differentiator rather than fake it — the platform survives on BUILD + centralized
  fallback; the pitch changes.
